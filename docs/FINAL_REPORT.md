# PE6201 Course Materials Q&A Assistant: Final Project Report

## Problem and intended impact

I built the PE6201 Course Materials Q&A Assistant to help a student revising for assignments or an examination find a course-grounded answer without manually searching many lecture and exercise PDFs. The course announcement describes a substantial learning corpus: 19 hours of classes, more than 500 slides, over 35 pre-reads, seven case studies, and six code scripts. My current prototype indexes a narrower, text-based subset of nine PDFs. The problem is not that students lack a general chatbot; it is that a general chatbot may not know the instructor's wording, may combine material from different weeks, and may give an answer without showing where it came from.

My primary persona is a PE6201 student who remembers a topic but not which lecture or exercise page covered it. The intended change is that the student can ask a question, inspect the passage and page supporting the answer, and decide whether the explanation is sufficient. I have not conducted a user study or timed manual search, so I do not claim a measured reduction in revision time or an improvement in grades. My demonstrated outcome is retrieval and evidence access, not learning gain.

## Why I chose retrieval-augmented generation

I chose a document-grounded retrieval design rather than a generic autonomous agent. The question-answering task needs to find relevant course evidence and explain it; it does not require planning actions across external tools. The app extracts text locally from uploaded PDFs, splits it into passages, and ranks passages with a keyword/BM25-style scorer. It supports a source filter when the student knows which PDF to search. The default answer is a local extractive response. If the student checks an explicit consent box, the app can send the question and up to four retrieved excerpts to OpenRouter's `openai/gpt-6-luna` for synthesis. It displays the retrieved excerpts with file, page, and source IDs so the student can check the answer.

The local path is my non-LLM baseline. It costs no model tokens, avoids sending course excerpts externally, and gives a reproducible comparison. The hosted LLM can make a concise answer from several excerpts, but it adds latency, provider dependence, privacy considerations, and citation risks. I keep the model optional and retain local retrieval and abstention when the model is unavailable. The app limits its own tracked spend at US$4.50, leaving US$0.50 below the US$5 project budget. This limit does not cover other uses of the same OpenRouter account.

## Data and evaluation

My indexed corpus contains nine PE6201 PDFs and 221 passages. The source PDFs are included with this course submission so the evaluator can reproduce the corpus; sharing them beyond the intended course-review audience would require checking the course-material distribution rules. The repository also includes a fixed 68-question evaluation set: 46 development questions and 22 held-out test questions. Each case records whether the answer is present, a reference answer, an expected source and page, and a short evidence note. Each split has six unanswerable questions. I use only the development split to select the abstention threshold; the current threshold is 0.40.

My local evaluation measures answerability precision and recall, evidence-page Hit@4, and reference token F1. On the latest local snapshot, development precision was 0.91 and recall was 1.00; test precision was 0.88 and recall was 0.94. Target-page Hit@4 was 0.88 on development and 1.00 on test. Macro-average Hit@4 across file/split groups was 0.91. These results suggest the retriever usually includes the expected test page among its top four passages, while the abstention threshold still misses one answerable test case.

In the latest OpenRouter comparison, all 22 binary answerability decisions were correct, 15 of 16 answerable questions cited the single expected source/page, and mean reference token F1 was 0.548 compared with 0.224 for the local answer baseline. This evaluation uses the revised prompt and citation validation. The first number is answerability accuracy only: it says the model answered or abstained consistently with the binary label, not that every factual answer was correct. Q020 illustrates the gap: its answerability decision was correct, but its token F1 was only 0.163 because the response named governance where the reference emphasized maintenance budgeting. The page metric can also penalize a valid citation to another supporting page; Q056 cited lecture notes that contain the three request types, while the single gold annotation names an exercise page. The lexical F1 rewards shared words and can underrate a correct paraphrase. I therefore treat these measures as useful signals, not as semantic ground truth.

## Implementation choices and difficulties

I kept PDF ingestion, local storage, retrieval, source selection, abstention, citation display, quiz selection, and evaluation code in the repository. I rent only the optional hosted language model. I added duplicate-file cleanup and visible file/passage counts after discovering that a multiple-PDF upload could be mistaken for a single indexed file. I also made the model key a launch-session setting rather than a source-code value, and added an explicit on-page consent step. Source filtering addresses the difference between an exercise's wording and the lecture notes' wording. The model prompt asks for course terminology and a direct answer, while citation validation rejects IDs that were not in the retrieved evidence.

The current privacy and safety controls are appropriate for a local study prototype: no model call without the consent checkbox, a local spend ledger, a per-request reserve, capped input excerpts and output tokens, and an instruction to treat excerpts as untrusted reference data. The app binds to `127.0.0.1` and has debug mode off. However, the Flask session key is hard-coded in the current code; I should replace it with a private environment variable before any network deployment. The uploaded PDFs, generated index, and API ledger are local files. A deployment would need separate access control, secret management, and a production server.

## Limitations and future path

The evaluation set is small: one test case changes a rate by about 4.5 percentage points across all 22 cases and 6.25 points among the 16 answerable questions. I authored project-specific questions while working with the same course PDFs, so the set may reflect my wording and miss questions students actually ask. Future evaluation should add independently authored paraphrases, cross-file questions, misleading keyword matches, unsupported questions, and multiple acceptable evidence pages. A human reviewer should label both factual correctness and whether each citation truly supports its claim. I also need a small usability study that times how long students take to find and verify answers, with consent and a clear purpose notice.

The current parser supports text-based PDFs, not OCR for scanned pages. Tables, diagrams, and formulas may be incomplete. The quiz self-check is based on keyword overlap, so it can mark a valid paraphrase as weak. I would improve the project first by strengthening answer and citation evaluation, then by making a course concept map that links related ideas across weeks and directs students to the supporting pages. I would not add autonomous tool actions unless a real learning task needs them.

## Conclusion

This project makes a modest but testable difference: it turns a subset of PE6201 PDFs into a searchable, evidence-visible study assistant with a local baseline and an optional LLM layer. Its strongest contribution is not autonomy; it is the combination of course-specific retrieval, source inspection, abstention, user-controlled external processing, and an explicit budget. The current results are promising for retrieval and answerability, but the small test set and weak semantic evaluation limit the claims I can make. Before presenting stronger claims about learning value, I need a larger independently worded test set and human-checked answer and citation judgments.
